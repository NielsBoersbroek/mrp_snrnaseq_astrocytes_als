6. Differential abundance with Milo

Author

Niels Boersbroek

Published

September 29, 2026

About this analysis

Cell composition analysis with scCODA tests differences in cell abundance across variables, but can only do so at the level of coarse clusters. Milo allows for a more granular approach, calculating partially overlapping neighborhoods and testing their enrichment.

theme_quarto() and theme_manuscript()

I created my own themes to add to figures. theme_quarto() is used to add themes to figures as displayed in the Quarto document and saved to disk as .pdf or .png. theme_manuscript() is used to add themes to figures as they will end up in the manuscript. I can already add arguments with theme() or specific themes (e.g. theme_classic(), my personal favourite) to plots; adding theme() afterwards keeps whatever was added in theme() before it, unless I specify that arugment here - that’s why I allowed to specify some things within my functions as well.

theme_quarto <- function(
    legend_position = "right", 
    plot_title = element_blank()
    ) {
    theme(
      plot.title = plot_title,
      legend.position = legend_position
    )
}

theme_manuscript <- function(
    legend_position = "none",
    plot_title = element_blank(),
    axis_title_size = 8,
    axis_text_size = 6
    ) {
    theme(
      plot.title = plot_title,
      legend.position = legend_position,
      axis.title = element_text(size = axis_title_size),
      axis.text = element_text(size = axis_text_size),
      legend.key.size = unit(0.4, "cm"), 
      legend.text = element_text(size = 8),
      legend.title = element_text(size = 9)
    )
}

save_plot()

This document displays all the figures I make, but I also want them saved to disk — both as .png and .pdf. I only need to provide the ggplot object, a filename (without extension), and optionally the width and height of the figure and additional arguments put into themes.

The figures for my written report contain subfigures spread across multiple scripts. Since I want to assemble these panel figures via R code rather than by hand, save_plot() can also optionally save the plot object itself to disk as an .rds file, for a final script to later combine with patchwork. Set figure to the name the figure should carry in the report (e.g. "SF1A") to trigger this; leave it NULL (the default) to just save the .png/.pdf as normal.

A live ggplot object carries its underlying data along with it — for plots built from large Seurat objects, this can balloon the saved file to gigabytes. To avoid this, save_plot() converts the object to a grob (a static, pre-rendered drawing, with no data attached) before saving it as .rds. This is controlled by the grob argument, and defaults to TRUE, since converting a small plot costs nothing but forgetting to convert a large one is expensive. Set grob = FALSE only if a later step specifically needs the original, live ggplot object rather than its rendered form.

save_plot <- function(
    p, filename, 
    width = 10, height = 6, 
    figure = NULL, grob = TRUE, apply_theme = TRUE, 
    add_tag = TRUE, tag_text_size = 14,
    legend_pos_manuscript = "none"
    ) {
  ## Save image on disk as png and pdf
  # Add Quarto-specific theme, unless the plot has its own custom theme
  if (apply_theme) {
    p_image <- p + theme_quarto()
  } else {
    p_image <- p
  }
  file_png <- file.path(dir_fig, paste0(filename, ".png"))
  ggsave(file_png, p_image, width = width, height = height, dpi = 150)
  file_pdf <- file.path(dir_fig, paste0(filename, ".pdf"))
  ggsave(file_pdf, p_image, width = width, height = height, dpi = 150)
  
  ## Save the ggplot object on disk as an rds file 
  if (!is.null(figure)) {
    # Add tag if needed
    if (add_tag) {
      tag <- str_extract(figure, "[A-Z]$")
      p <- p + 
        labs(tag = tag) + 
        theme(
          plot.tag = element_text(
            face = "bold", 
            size = tag_text_size, 
            hjust = 0, vjust = 0
            )
        )
    }
    # Add manuscript-specific theme, unless the plot has its own custom theme
    if (apply_theme) {
      p <- p + theme_manuscript(legend_position = legend_pos_manuscript)
    }
    file_rds <- file.path(dir_man, paste0(figure, ".rds"))
    # Convert the object to a grob if needed
    if (grob) {
      p <- ggplotGrob(p)
    }
    # Save on disk
    saveRDS(p, file_rds)
  }
}

print_tabset()

Quarto cannot cross-reference figures that are made inside a loop. To still display the plots of a loop in this document, I collect them in a named list and show them as tabs with print_tabset(). The names of the list become the tab titles. It also accepts data frames (shown as a table). This function writes raw Quarto markdown, so the chunk that calls it needs the chunk option #| output: asis. heading_level should be one deeper than the heading above the chunk.

print_tabset <- function(obj_list, heading_level = 3) {
  cat("::: {.panel-tabset}\n\n")
  for (nm in names(obj_list)) {
    cat(strrep("#", heading_level), " ", nm, "\n\n", sep = "")
    obj <- obj_list[[nm]]
    if (inherits(obj, "ggplot")) {
      print(obj)
    } else if (is.data.frame(obj)) {
      cat(knitr::kable(obj, format = "pipe"), sep = "\n")
    }
    cat("\n\n")
  }
  cat(":::\n\n")
}

Running Milo

Convert Seurat to Milo object

Milo requires its own type of object, the “Milo object”. To do so, I first had to convert my Seurat object to an sce object, after which I could turn the sce object into a milo object.

file_rds <- file.path(dir_data, "seu_shortread_astros_clustered.rds")
seu <- readRDS(file_rds)

## Seurat needs to be converted to sce
# Convert to an sce object
sce <- as.SingleCellExperiment(seu)
# Milo requires a specific milo-object. The major differences between the Milo
# and SingleCellExperiment object are in the extra slots of the Milo object,
# such as those where nhood values are stored.
milo <- Milo(sce)

# Store the previously computed PCA and UMAP to the milo object
# For the PCA, use the integrated reduction ("harmony")
reducedDim(milo, "PCA") <- Embeddings(seu, reduction = "harmony")
reducedDim(milo, "UMAP") <- Embeddings(seu, reduction = "umap")

# Remove the Seurat and SCE objects to save memory
rm(seu)
rm(sce)

Run Milo

I used all default settings to run Milo. One can change the k parameter in defining variables, I deliberately set this at 10.

# Construct a KNN graph. As I transfered the reduction "harmony" to the
# reductionname "PCA", it will automatically use this reduction for all
# following steps.
milo <- buildGraph(
  milo,
  k = k,
  d = 50, # default setting
)
# Define neighbourhoods. Settings are default
# This uses stochasticity, so set a seed
set.seed(42)
milo <- makeNhoods(
  milo,
  prop = 0.1,
  k = k,
  d = 50, # default setting
  refined = TRUE,
)

If the number of cells per neighborhood is too low, I should adapt the k parameter (tutorial recommends to have the distribution peaking above 20). It works well with my set k.

p_nhoodsize <- plotNhoodSizeHist(milo)
p_nhoodsize

The rest of milo works by analysing the cell counts per neighborhood per sample. In my data, the sample is given with the column “AnonymousID”.

milo <- countCells(
  milo,
  meta.data = data.frame(colData(milo)),
  sample = "AnonymousID"
)

To perform differential abundance testing with Milo, I need an additional dataframe with metadata. In my case, I want to test for the column “condition” (= ALS vs Ctrls). I first ran Milo months ago and my dplyr skills were not yet that good back then, so I got the solution below from here. Might as well still use it, but credit where credit’s due.

milo_design <- colData(milo) |>
  data.frame() |>
  select(AnonymousID, condition) |>
  distinct() |>
  remove_rownames() |>
  column_to_rownames("AnonymousID")
# Reorder rownames to match columns of nhoodCounts()
order_rows <- colnames(nhoodCounts(milo))
milo_design <- milo_design[order_rows, , drop = FALSE]
milo <- calcNhoodDistance(milo, d = 50) # Same d as buildGraph()

da_results <- testNhoods(
  milo,
  design = ~condition,
  design.df = milo_design
)

Add metadata to results by annotating neighborhoods by condition

# Annotate neighborhoods by condition
da_results <- annotateNhoods(milo, da_results, coldata_col = "condition")
# Categorize neighborhoods with < 70% of one condition as mixed
da_results$anno_condition <- ifelse(
  da_results$condition_fraction < 0.7,
  "Mixed",
  da_results$condition # The neighborhoods which are not mixed get ALS or Ctrl
)

Find group structure of neighborhoods. In practice, it runs louvain clustering to identify neighborhoods which are overlapping and thus similar to each other. The max.lfc.delta argument determines the cutoff of fold change, and can kind-of be considered like the resolution of a clustering algorithm. With one, I set it quite low.

The neighborhood graph is needed to map the results to an embedding. Each node will represent a neighbourhood and each edge indicates the number of cells the neighbourhouds have in common.

# Find group structure of neighborhoods
da_results <- groupNhoods(milo, da_results, max.lfc.delta = 1)

# Build a graph across the neighborhood groups
milo <- buildNhoodGraph(milo)

plotNhoodGraphDA directly visualizes the da_results, whereas plotNhoodGroups plots the groups created with groupNhoods. The alpha is the FDR significance threshold (0.05 is default). You can see that there are no clear ALS-enriched or -depleted populations.

p_nhood_da <- plotNhoodGraphDA(milo, da_results)
p_nhood_da
p_nhood_groups <- plotNhoodGroups(milo, da_results) +
  theme(legend.position = "none")
p_nhood_groups
p_nhood_da + p_nhood_groups

Also test one where I do not set a significant threshold at all. Even then, you do not see clear ALS-enriched or -depleted populations.

p_nhood_da_loose <- plotNhoodGraphDA(milo, da_results, alpha = 1)
